## 1. Введение и бизнес-цель

### 1.1. Текущие проблемы в UCM
1. **Отсутствие автоматизации доставки KRL:** При отзыве сертификатов пользователей (`User CA`) в UCM формируется KRL (Key Revocation List), однако на целевые серверы он автоматически не доставляется. Скомпрометированные ключи продолжают приниматься серверами до ручного вмешательства администратора.
2. **Ручной жизненный цикл SSH Host-сертификатов:** Серверные host-сертификаты (`Host CA`) требуют ручного экспорта публичных ключей хостов, их подписания в UCM и ручной раскладки на серверы. Автоматического продления сертификатов хостов до истечения их срока действия нет.
3. **Ошибочность Push-to-SSH подхода:** Попытка управлять серверами через прямое подключение UCM по SSH (хранение приватных SSH-ключей/root-доступов в UCM) создает критическую уязвимость, требует прямой сетевой связности UCM к серверам (не работает за NAT/Firewall) и раздувает кодовую базу.

### 1.2. Решение
Инверсия контроля: внедрение **Pull-модели** с автономным легковесным скриптом-агентом на сервере (`ucm-ssh-agent`), двухуровневой системой токенов, коротким интервалом опроса агента за KRL (15 минут, см. дополнение), защищенными Guard Rails жизненного цикла и выделенным разделом UI **`/ssh/hosts`**.

## 2. Разделение ответственности User CA и Host CA

В OpenSSH на сервере четко разделены две роли:
1. **User CA (Вход пользователей):**
   * Сервер доверяет пользователям по `TrustedUserCAKeys /etc/ssh/user_ca.pub`.
   * Сервер отклоняет отозванных пользователей по `RevokedKeys /etc/ssh/user_krl`.
   * **KRL на сервере на 100% относится к User CA.** Доставка KRL публична, не требует авторизации и секретов.
2. **Host CA (Идентификация сервера):**
   * Сервер доказывает клиентам свою подлинность через `HostCertificate /etc/ssh/ssh_host_ed25519_key-cert.pub`.
   * Выпуск и автопродление относятся к **Host CA** и требуют точечной авторизации (Host Token).

## 3. Архитектура и модель данных (Backend)

### 3.1. Модель `SSHManagedHost` (`ssh_managed_hosts`)
Новая таблица в базе данных UCM:

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | Integer (PK) | Идентификатор записи |
| `hostname` | String(255) | FQDN сервера (Unique index) |
| `host_ca_id` | Integer (FK $\to$ `ssh_cas.id`) | Ссылка на Host CA (для host-сертификата) |
| `user_ca_id` | Integer (FK $\to$ `ssh_cas.id`, Nullable) | Ссылка на User CA (для раскатки KRL и trust pubkey) |
| `token_hash` | String(64) | SHA-256 хэш постоянного токена хоста |
| `token_prefix` | String(16) | Первые символы токена для идентификации в UI (например, `ucm_sh_9a2f`) |
| `public_key` | Text | Открытый ключ сервера (`ssh-ed25519 AAA...`) |
| `principals` | Text (JSON) | Зафиксированный список principals хоста |
| `current_cert_id` | Integer (FK $\to$ `ssh_certificates.id`, Nullable) | Ссылка на действующий сертификат хоста |
| `auto_renew` | Boolean (Default: True) | Флаг разрешения автоматического продления |
| `status` | Enum (`pending`, `active`, `revoked`) | Статус допуска и сертификата хоста |
| `last_seen_at` | DateTime, Nullable | Время последнего обращения |
| `last_krl_sync_at`| DateTime, Nullable | Время последней успешной синхронизации KRL |
| `last_renew_at` | DateTime, Nullable | Время последнего продления host-сертификата |
| `last_ip` | String(45), Nullable | IP-адрес последнего контакта |
| `created_at` | DateTime | Время регистрации |

### 3.2. Расширение модели `SSHCertificateAuthority`
Для Host CA (`ca_type == 'host'`):
* `host_cert_ttl`: Integer (default: `2592000` — 30 дней) — срок действия хост-сертификатов (изолирован от суточного дефолта User CA).
* `renew_threshold_percent`: Integer (default: `30`%) — порог начала продления сертификата.

### 3.3. Жизненный цикл токенов (Security Model)
1. **Bootstrap Token:**
   * Одноразовый короткоживущий токен (TTL: 1–4 часа).
   * Используется только в команде первичной установки (`curl ... | sudo bash`).
2. **Host Token:**
   * Генерируется сервером UCM при `enroll` (`ucm_sh_<random>`).
   * В базе сохраняются только `token_hash` и `token_prefix`. Plaintext возвращается клиенту ровно один раз.
   * Строгий скоуп: разрешает только вызовы `/renew` и `/check-in` для своего `host_id` и `host_ca_id`.
   * **Ротация (`POST /api/v2/ssh/hosts/<id>/rotate-token`):** генерирует новый токен, инвалидирует старый, логирует действие в аудит.
   * **Инвалидация:** при переходе в `revoked` значение `token_hash` стирается (`NULL`).

### 3.4. Публичный кэшируемый KRL (`/ssh/krl/<refid>`)
* Публичный эндпоинт без авторизации.
* **Защита от DoS:** Кэширование скомпилированного KRL-бинарника в памяти/БД. `ssh-keygen -k` вызывается только в момент отзыва сертификата, а не на каждый HTTP-запрос.
* **HTTP Кэширование:** `ETag` вычисляется от хэша списка серийников и даты последней ревокации. На запросы с `If-None-Match` возвращается `304 Not Modified`.
* Защита стандартным `rate_limiter` UCM.

### 3.5. Guard Rails жизненного цикла (Конечный автомат)
1. **Выключение автообновления (`auto_renew = False`):**
   * Действующий сертификат **не отзывается**, сервер работает до его `valid_to`.
   * Запросы на `/renew` возвращают `403 Forbidden: Auto-renewal is paused`.
2. **Отозвать доступ хоста (`Revoke Host Access` / Деавторизация сервера):**
   * Действующий сертификат хоста отправляется в KRL Host CA.
   * `auto_renew` переводится в `False`, статус хоста переходит в `revoked` (`Blocked`).
   * Токены хоста аннулируются навсегда.
3. **Удаление хоста (`Delete Host`):**
   * **Блокировка:** Запрещено удалять хост, пока `auto_renew == True` и сертификат действителен.
   * Разрешено удалять только если:
     а) `auto_renew == False` (плановый вывод), ИЛИ
     б) доступ хоста уже отозван (`status == revoked`).

## 4. Доставка отзыва (pull-модель, по решению issue #451)

При нажатии `Revoke Host Access` в UCM:
1. UCM мгновенно пересобирает бинарник KRL и обновляет ETag/`krl_version` (публичный
   `/ssh/krl/<refid>` становится другим сразу же).
2. Агент на таймере (15 минут) обращается к `/ssh/krl/<user_ca_refid>` с `If-None-Match`;
   при изменении версии — атомарно заменяет `/etc/ssh/ucm_user_krl` и делает `sshd reload`.
3. `check-in` сообщает агенту, что KRL сдвинулся (etag расходится) и что пора продлевать
   сертификат; UCM никогда не обращается к серверу сам.

Гарантия доставки отзыва — не секунды, а интервал таймера; этого достаточно по решению
мейнтейнера ("a short polling interval against the cached KRL is enough").

## 5. Клиентский агент (`ucm-ssh-agent`)

* Единый POSIX sh скрипт (`/usr/local/bin/ucm-ssh-agent`) + `systemd.service` + `systemd.timer`.
* Конфиг `/etc/ucm/agent.conf` (права `0600`):
  * Секция `[host_certificate]`: `enabled`, `host_token`, `ca_refid`, пути к файлам хост-ключа и сертификата.
  * Секция `[user_ca_trust]`: `enabled`, `ca_refid`, пути к `user_ca.pub` и `user_krl`.
* Выполняет:
  * Синхронизацию KRL каждые 15 минут (ETag/304; мгновенных сигналов нет — issue #451).
  * Проверку остатка срока host-сертификата: если $\le 30\%$ — запрашивает `/renew`, атомарно заменяет сертификат и перезагружает sshd.

## 6. Пользовательский интерфейс (UI / UX)

### 6.1. Раздел `SSH Hosts` (`/ssh/hosts`) в боковом меню
Выделенная страница (`ResponsiveLayout` + `ResponsiveDataTable` + Slide-Over Drawer):

* **Колонки таблицы (чистые, без смешения):**
  1. **Host:** FQDN сервера + IP-адрес последней связи.
  2. **Host CA:** бейдж с именем Host CA.
  3. **Host Certificate:** статус сертификата (`Valid`, `Expiring`, `Expired`, `Revoked`) + дата окончания и серийный номер.
  4. **Auto-Renew:** интерактивный переключатель `ON` / `OFF`.
  5. **User CA:** бейдж с именем доверенного User CA (или `—`).
  6. **KRL:** статус синхронизации KRL (`Synced 3m ago`, `Never synced`).
  7. **Agent:** статус агента (`Online 2m ago`, `Offline 12h ago`, `Blocked`).
* **Действия над строкой (`rowActions`):**
  - `Details` (открыть панель детальной информации)
  - `Reinstall` (повторный выпуск команды установки)
  - `Revoke Host Access` (отозвать доступ хоста / деавторизация, если активен)
  - `Delete Host` (удаление, если отключен auto-renew или хост отозван)
* **Боковая панель деталей (Slide-Over Drawer):**
  - Шапка: FQDN, статус (`Active` / `Revoked`), последний IP.
  - Секция 1: **Host Identity (Host CA)** — имя Host CA, статус сертификата, серийный номер, срок действия, интерактивное управление автопродлением.
  - Секция 2: **User Access Trust & KRL (User CA)** — имя доверенного User CA, статус и отметка последней синхронизации KRL, пояснение назначения (`sshd TrustedUserCAKeys` / `RevokedKeys`).
  - Секция 3: **Agent Connectivity** — статус агента (`Online`/`Offline`/`Blocked`), время последней активности, IP, префикс токена.
  - Панель быстрых действий: `Reinstall Agent`, `Revoke Host Access`, `Delete Host`.

### 6.2. Мастер подключения (`+ Connect Server`)
Модальное окно с выбором Host CA, User CA и генерацией однострочника Quick Install:
```bash
curl -sSL "https://ucm.example.com/ssh/setup?host_ca=uuid1&user_ca=uuid2&token=boot_abc" | sudo bash
```
